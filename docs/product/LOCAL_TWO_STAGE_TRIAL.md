# 開局站位與二段跑位：本地試作

日期：2026-10-02（香港）。分支：`local/two-stage-movement`。
基底：v0.3.7，`60c44fd8fc6c167336062f82f769ae698d0944f4`。

依使用者要求，僅在雲端工作區本地開發、測試。沒有 push、PR、GitHub 寫入或公開部署。公開版本與 package/version.json 發布版本未遞增；首頁另標示「本地试验」。

> 以下為初版試作紀錄；目前操作以文末 v0.3.11 為準。

## 試玩順序

1. 進入畫板 → 右上角「⋯」→「开局站位」。四張小球場分別為一區／二區發球與接發。藍色固定是我方，紅色固定是對手，球在發球方。
2. 從網球畫出第一拍。可先拖剛擊球的球員到準備位置，這是第一段提前回位；也可跳過。
3. 拖接球方到接球位置，再從網球畫回球。
4. 拖原球員到新的接球位置，這是第二段接球跑位。
5. 點播放：第一段與我方擊球同步，第二段與對手回球同步，兩段在對手擊球時連續銜接，不增加拍次。
6. 頂部循環箭頭隨時旋轉視角 180°。球場上的拖曳方向跟隨新視角，文字保持正向。

再次拖同一球員可改該段終點，不會追加空拍；撤銷／重做一次對應一次拖曳。拖曳時球員跟隨手指，放開才提交，取消手勢還原。替換已有拍次、路線或備註的畫板會先顯示確認，可取消或撤銷。

- `output/local-two-stage.mp4`：真實瀏覽器操作錄影。
- `output/opening-menu.png`、`output/touch-drag.png`、`output/rotated-board.png`：畫面截圖。
- 旋轉只影響目前編輯器視角；重開恢復預設視角，JSON 及分享輸出仍使用原本的戰術座標。
- 球員移動目前與各拍球路共用進度；未增加分腿墊步、獨立起跑延遲、遊戲計分或判斷關卡。先測拖曳是否好用再決定後續規則。

## v0.3.10：二段跑位選項（2026-10-03）

首次使用預設一段跑位。「⋯」畫板菜單的「跑位」區可直接開啟二段跑位，瀏覽器會記住選擇。關閉時，自動接續只允許拖接球方畫單段跑位；要拖剛擊球的球員提前回位，必須先開啟選項。已保存的二段路線與示例仍完整播放，不會因切換而刪除。

本次 Chromium 390×844／320×740 驗證：預設關閉、阻擋新增提前回位且文件不變、開啟後可畫兩段、關閉後保留原路線、開關狀態刷新回顯、接球方單段接續、觸控跟手、旋轉及示例播放。TypeScript、受保護 runtime 與建置／Sites 檢查另行通過。未做實體 iPhone 驗收。

## v0.3.11：連續拖曳不再覆蓋第一段（2026-10-03）

開啟菜單「二段跑位」，畫出我方擊球後：第一次拖我方球員畫提前回位，第二次從第一段終點拖同一球員，接出第二段。也可先畫對手回球再補第二段。修改第一段請選路線端點調整。四種開局繼續在菜單直接選。

第二段可先保存；尚未畫對手回球時只播放已有擊球拍次，不讓第二段提前跑。補上對手回球後，第一段配我方擊球，第二段配對手回球。

Chromium 手機視窗 390×844／320×740：45 項模型、媒體及操作案例通過，包含連續拖曳保留第一段、兩段座標銜接、取消／撤銷／重做、刷新、JSON 往返、播放拍次、觸控和切換選項後重新繪製。未做實體 iPhone 驗收。

WebKit 同尺寸補驗連續兩次拖曳、切換後繪製、未配回球的第二段保存與刷新：3 項通過。

## v0.3.12：依球的時序安排跑位（2026-10-03）

本節取代 v0.3.11 的「發球方可連拖兩次預畫接球」規則。

1. 畫發球，提示優先指向接發球方。第一拖調整方向、第二拖變向接球；兩段屬於同一個來球，不增加拍次。
2. 發球方可補提前回位。播放第一拍時，球飛行、接發兩段、發球方回位同時進行。
3. 畫對方回球，再拖原發球方接球；這段從上一拍的回位終點接續。還沒畫回球就重拖發球方會得到明確提示，不改掉回位。
4. 可直接跑到接球點，不強迫畫滿兩段。關閉二段選項保留所有已畫路線。

同拍兩段以可選 `via` 轉向點保存，仍為一條 move 路線；沒有新空拍。兩段在該次來球時間內按球場距離分配進度，屬戰術示意，不是人體跑速模擬。轉向點控制第一段，終點控制第二段；JSON、複製、撤銷、刷新、圖片與播放共用幾何。舊曲線不自動轉直，v0.3.11 已保存的預畫接球也不清除。

UI 檢查：四種開局及開關維持菜單直接選；提示改為球員＋階段，避免第一步後就誤導畫回球。兩段標出 1、2；44px 提示關閉區，錯誤提示出現時暫時隱藏重疊的「找打法」按鈕。完整截圖為本次瀏覽器操作留存，不含個人資料。

驗證環境：Linux／Node 22、Playwright Chromium 390×844／320×740 與 WebKit 390×844。模型核對轉向時刻、同時移動、拍次、JSON 壞資料、舊資料保留；操作核對同拍二段、發球方回位／接球、觸控、180° 旋轉、兩個端點独立修改、取消／撤銷／重做、刷新、單段預設及既有 D 組。沒有實體 iPhone 或 VoiceOver 驗收；截圖不能證明完整無障礙符合性。

## v0.3.13：精簡引導與菜單（2026-10-03）

使用者確認跑位流程跑通。本版不改資料模型、拖曳時序及播放，只整理 UI：單行球員／動作引導、半透明分組菜單、四種站位直選、滑動式二段開關，以及合併的画板操作組。操作說明縮短，圖標對照用 disclosure 按需展開。

保留 44px 關閉區、原生滑動關閉、底部場地設定及 D3「分區已開／已關」文案。提示關閉鍵固定在側邊，避開旋轉後的球員起點。提供降低透明度與減少動態效果的 CSS 適配。沒有變更受保護的 mobile runtime，也未推送 GitHub。

## v0.4.0：收斂為正式畫板介面（2026-10-03）

首頁和編輯器共用固定的品牌／版本頂欄。首頁主動作只有「畫板」，新建、畫板庫和內容說明以圖標放在底部；最近畫板仍可上滑查找。移除試驗標籤、二段試看示例入口和首頁的用途／打法文字按鈕。

編輯 dock 固定提供返回、添加、播放、刪除／拍次和展開。展開是一級常用操作：撤銷、重做、180° 調換、拍次和設定。完整畫板菜單為二級，內含四種開局直選、二段跑位、操作提示、名稱、備份分享、畫板庫、參考和場地顯示。展開不改變球場尺寸；調換後收起，避免遮擋旋轉後的拖曳起點。

操作氣泡伴隨目前的球或接球方，依序顯示「拖球發球」「先調整」「變向接球」「拖球回擊」。沒有 ×，不接收指標事件；拖曳時跟隨，播放及打開面板時隱藏。「操作提示」預設開啟，獨立記住選擇；二段模式切換不改動該偏好。跑位資料模型與已驗收時序不變。

交付仍使用現有獨立 Site，未推送 GitHub、未改動 GitHub Pages。實體 iPhone Safari、系統鍵盤與 VoiceOver 不在本次自動化環境內。

# 開局站位與二段跑位：本地試作

日期：2026-10-02（香港）。分支：`local/two-stage-movement`。
基底：v0.3.7，`60c44fd8fc6c167336062f82f769ae698d0944f4`。

依使用者要求，僅在雲端工作區本地開發、測試。沒有 push、PR、GitHub 寫入或公開部署。公開版本與 package/version.json 發布版本未遞增；首頁另標示「本地试验」。

## 試玩順序

1. 進入畫板 → 右上角「⋯」→「开局站位」。四張小球場分別為一區／二區發球與接發。藍色固定是我方，紅色固定是對手，球在發球方。
2. 從網球畫出第一拍。可先拖剛擊球的球員到準備位置，這是第一段提前回位；也可跳過。
3. 拖接球方到接球位置，再從網球畫回球。
4. 拖原球員到新的接球位置，這是第二段接球跑位。
5. 點播放：第一段與我方擊球同步，第二段與對手回球同步，兩段在對手擊球時連續銜接，不增加拍次。
6. 頂部循環箭頭隨時旋轉視角 180°。球場上的拖曳方向跟隨新視角，文字保持正向。

再次拖同一球員可改該段終點，不會追加空拍；撤銷／重做一次對應一次拖曳。拖曳時球員跟隨手指，放開才提交，取消手勢還原。替換已有拍次、路線或備註的畫板會先顯示確認，可取消或撤銷。

## 本地驗證

環境：Linux、Node 22、Playwright Chromium / WebKit；手機尺寸 390×844、320×740，加上既有桌面回歸尺寸。瀏覽器使用隔離 profile，無使用者資料。

| 項目 | 驗證及結果 |
| --- | --- |
| 四種開局 | 逐一操作菜單，核對我方／對手座標、發球方持球、第一拍和撤銷：通過 |
| 替換保護 | 已畫球路後取消替換內容不變，確認替換後撤銷可恢復：通過 |
| 可選二段跑 | 實際拖曳我方擊球→提前回位→對方接球與回球→我方接球；省略提前回位沿用舊操作：通過 |
| 調整與連續性 | 重複拖曳不退出自動接續；兩段交界座標相同，原球路不變：通過 |
| 播放及保存 | 維持兩拍，兩階段插值有位移，撤銷重做、取消手勢、刷新重開：通過 |
| 180° 視角 | 旋轉不修改文件；旋轉後按實際畫面座標拖出第二拍：通過 |
| 觸控跟手 | Chromium CDP 真實觸控事件完成兩段；像素檢查拖曳中球員位於手指終點；320px 工具列無重疊：通過 |
| 既有回歸 | v0.3.2 多拍、v0.3.3 舊球路端點防護、issue #11 分區標籤／場地／選取恢复、模型及存儲：通過 |
| 工程檢查 | TypeScript、28 個受保護 runtime 文件、內容檢查、release preflight、本地建置：通過 |

Chromium 共 64 個不同案例通過（分批跑）；WebKit 7 個本次互動案例通過，CDP 專用觸控案例不適用 WebKit。觸控像素檢查初次發現控制柄覆蓋球員，修正為拖曳中隱藏控制柄後重跑通過。未做實體 iPhone Safari 驗收。

案例：`tests/local-two-stage.spec.ts`、`tests/board-model.spec.ts`、`tests/v032-rally-authoring.spec.ts`、`tests/v033-rally-guard.spec.ts`、`tests/issue11-editor.spec.ts`。

## 本地產物與邊界

- 預覽服務：此雲端工作區的 4192 埠，來源為此 worktree。不是 Mac mini 的 localhost，也不是可對外分享的部署。
- `output/local-two-stage.mp4`：真實瀏覽器操作錄影。
- `output/opening-menu.png`、`output/touch-drag.png`、`output/rotated-board.png`：畫面截圖。
- 旋轉只影響目前編輯器視角；重開恢復預設視角，JSON 及分享輸出仍使用原本的戰術座標。
- 球員移動目前與各拍球路共用進度；未增加分腿墊步、獨立起跑延遲、遊戲計分或判斷關卡。先測拖曳是否好用再決定後續規則。
- 原生工作區瀏覽器預覽工具在本次環境不可用；本地 HTTP 服務、Playwright 瀏覽器測試和錄影已啟動／完成，沒有為提供連結而擅自部署。

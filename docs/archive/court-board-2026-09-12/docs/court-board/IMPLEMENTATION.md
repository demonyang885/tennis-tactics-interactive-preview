核心流程：**選現有戰術／空白球場 → 擺場 → 畫球路與跑位 → 分階段示範 → 儲存並用於場上 drill**。

| 能力 | 首個可驗收版本 | 完成時的可見結果 |
|---|---|---|

| 球路與跑位 | 兩種清楚不同的線型；直線／曲線；端點與曲線控制柄 | 能畫出餵球、擊球與回位，調整彎曲程度 |

| 階段示範 | 新增、複製、刪除阶段；播放／暫停／逐階段；速度控制 | 同一球場依次完成餵球、擊球、回位及下一拍 |

## 3. 網頁與原生能力邊界

- 滑鼠、手指及一般瀏覽器 Pointer Events 是首版輸入方式。支援 Apple Pencil 的裝置可作一般指標輸入；不可宣稱具備原生 PencilKit、筆壓筆觸、雙擊切工具或完整防誤觸能力。
- 草稿保存於目前網站來源的瀏覽器儲存空間，不可宣稱 iCloud、自動跨設備同步或帳號備份。另一設備透過匯入 JSON 續編。不同預覽網域的本機草稿不會自動共享。
- 分享優先提供檔案下載；瀏覽器及裝置支援時才使用系統分享。PNG 匯出是靜態圖片；MP4／GIF、iCloud 同步及原生應用整合不列入首版完成承諾。
- 沿用 GitHub Pages 網頁部署與現有手機預覽 runtime。真實設備的儲存、檔案分享及觸控須實機確認，不能用桌面模擬結果宣稱全部一致。

## 5. 可重用資料結構

畫板草稿是獨立的 `BoardDocument`，不直接寫入現有 `Tactic[]`。現有 `Tactic` 必須有至少三幀、合法的遞增時間及完整教學文案；空白畫板可從單幀開始，兩者驗證規則不應混用。

建議文件包含：

```ts
type BoardDocument = {
  version: 1;
  id: string;
  title: string;
  sourceTacticId?: string;
  updatedAt: string;
  court: CourtConfig;
  entities: BoardEntity[];
  frames: BoardFrame[];
  transitions: BoardTransition[];
  marks: BoardMark[];
  drill?: DrillBrief;
};
```

- `BoardEntity`：穩定 ID、類型（球員／球／標誌碟／餵球籃）、角色及短標籤；各幀位置由 `BoardFrame.poses[entityId]` 指定。
- `BoardFrame`：穩定 ID、字幕、實體位置、可見標示 ID、停留時間。複製幀須深拷貝位置，不共享可變陣列。
- `BoardTransition`：起終幀 ID、時長與 `actions`。每個 action 包含 `entityId`、`kind: shot | move | feed`、局部開始／結束時間與直線／二次曲線控制點。起終點取自兩幀中該實體的位置，避免拖動球員後路線端點脫離。
- `BoardMark`：自由筆、註記、非動畫箭頭及目標區。自由筆是標示，只有明確建立的 action 才驅動回放。
- `DrillBrief`：目標、參與人數、器材、餵球任務、球員任務、次數／組數、成功條件、降低難度與升級方式；可引用 `frameId`／`transitionId`。

所有位置使用一致的場地座標，不保存畫面像素。球場內維持現有 `0–1` 座標，另明確定義並驗證可用的場外邊距，以放置籃筐與回位角色。轉接舊 `Moment[]` 時保留幀時間比例與站位；畫面大小、裝置比例及主題不改動文件座標。

刪除角色、幀或標示時同步處理其引用。未知版本、缺失引用、非有限數值、越界座標、過多節點或過大檔案要拒絕匯入並提供可理解的原因。使用者文字以文字節點呈現，不作 HTML 執行。

## 6. 角色命中、拖曳與曲線

1. 用共用幾何函數在畫面位置與場地位置之間轉換。SVG 作操作層時採用其反向 CTM；Canvas 模式則使用 holder 尺寸及同一套場地邊界，避免 device frame 縮放造成偏移。
2. 球員與球的可見半徑可小，但觸控命中區至少 44 CSS px。重疊時優先命中已選元素，其次依實際距離；另有「我方／對手／球」元素選取入口，避免球藏在球員下無法選。
3. 採用 Court Canvas 的固定工具心智模型：先點 `球路` 或 `跑位`，再直接從場上的網球或球員拖到終點；工具保持啟用，直到使用者切換。繪製工具忽略既有路線控制柄，只有 `選擇` 模式可移動與精確調整現有對象；`選擇` 的再次點按固定開啟語義對象列表，球員和標記面板負責低頻建立選項。畫布內使用 pointer capture，處理 pointer cancel；取消手勢不留下半成品或錯誤歷史。
4. 箭頭端點和曲線控制柄只在選取時顯示。控制柄可放大命中區，拖動後同步預覽。球路用實線，跑位用虛線，兩者兼具方向箭頭與文字圖例，不能只靠顏色。
5. 自由筆適度取樣與簡化；一次完整筆劃是一個可撤銷操作。目標區可拖移及縮放；第一版先限制規則圓形／矩形，避免複雜多邊形操作。
6. 畫布是需要擁有拖曳的區域，可局部使用 `data-scroll-drag="ignore"`／`touch-action: none`；一般工具或標示列表不能因此失去頁面捲動。水平幀列沿用 `Carousel`。

## 7. 階段動畫、歷史與儲存

播放時由相鄰幀的 action 推導位置，上一段終點必須等於下一段起點。移動路線沿曲線插值；球路與球員可設定不同開始時間，呈現先餵球、再擊球、再回位。階段字幕保持與當前動作同步。回放為教學示意，不是擊球物理模擬。

播放期間鎖住拖曳；切回編輯時停在所選階段。單幀可以擺場與匯出；不足兩幀時播放按鈕給出明確提示。刪除至一幀、從尾端重播、拖動進度或切換速度均不得產生空引用或 NaN。第一版可只允許最後一個階段刪除或在刪除後重建相鄰轉換，必須保持規則可見且一致。

撤銷／重做使用文件命令或前後快照；僅文件內容進歷史，選取、播放進度、面板開關不算編輯。拖曳中可即時預覽，pointer up 後提交一次；撤銷後新編輯清空 redo。文字輸入在確認或失焦時形成一筆命令，避免每個字都佔一筆。歷史設上限，避免長自由筆工作階段耗盡記憶體。

持久化包含版本及 `updatedAt`。自動儲存採 debounce，離开畫板前補寫；有儲存容量或存取錯誤時顯示「尚未保存」並提供 JSON 匯出。成功寫入後才顯示已保存。本機草稿列表支持重新開啟、複製及明確刪除；不以切换範本默默覆寫同一份草稿。

## 8. 匯出與既有內容、Drill 的關係

PNG 匯出使用與畫板相同的幾何、符號及路線，包含文件名稱、圖例和當前階段口令，移除控制柄、選取框與工具按鈕。使用足夠解析度保持手機放大後文字可讀。JSON 匯出包含完整階段、曲線、器材、標示及訓練說明；匯入後播放結果和可編輯內容應可重現。

現有 `TacticPlayer` 的「在畫板中調整」建立新副本，保留 `sourceTacticId`。不得因改球路而覆寫既有教學字幕或將使用者草稿當成正式校驗內容。組合採選擇片段或逐階段匯入，先保持既有互動分支正常運作；自由畫板並不自動生成對手分支。

Drill 後續以同一文件展示「擺場 → 餵球 → 執行 → 回位／下一拍」。首批仍可圍繞受壓高深中路、短球打深跟進、斜線等機會再變線。固定餵球、變化來球與條件對抗是各自的練習任務，不能只改動畫速度就稱為不同訓練等級。次數、目標區與升級門檻由教練按能力調整。

| 發布關卡 | runtime、內容、型別及 production build 通過；Pages 成品檢查通過；獨立預覽可開啟且標明對應提交 |

## 10. 建議執行順序

1. 展示三版主題，記錄使用者選擇；把選定畫板的版面、工具密度及色彩語意作為 UI 依據。
2. 建立獨立分支，完成資料模型、幾何、範本轉接與文件命令，再整合最小的角色拖曳與線路編輯。
3. 加入階段、曲線、器材和註記，再完成播放、撤銷／重做與本機儲存。
4. 接上現有戰術入口、PNG／JSON 及一個完整 drill 樣板，以實際任務檢查功能是否閉合。
5. 完成上述驗收；記錄通過與尚未支持項目，最後更新獨立預覽並交付可核對的 URL／提交。
